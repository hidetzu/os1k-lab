## セグメント方式とページ方式

メモリを区切る方法には、大きく2つの考え方がある（『はじめて読む486』第9章で知った）。

| | セグメント方式 | ページ方式 |
| --- | --- | --- |
| 区切り方 | 用途ごとに、大きさの違う領域に分ける（コード、データ、スタックなど） | 決まった大きさ（4KB）のかたまりに機械的に分ける |
| 表に書くもの | 領域の先頭（ベース）と大きさ（リミット）と属性 | ページごとの対応先と属性 |
| 良いところ | 「この領域はコード」と意味の単位で守れる | 大きさがそろっているので、空いたページをどこにでも当てはめられる |
| 苦手なところ | 大きさがばらばらなので、空きが虫食いになりやすい（486 本 p.85、`memory-allocation.md`） | 1つの領域が何ページにもまたがるので、表が大きくなる |

486 は両方を重ねて使う。RISC-V にはセグメントの仕組みがなく、ページングだけ（一般知識）。

```
486:     logical addr --(segment)--> linear addr --(paging)--> physical addr
RISC-V:  virtual addr ------------------------------(paging)--> physical addr
```

- 今の汎用 OS（Linux など）は、x86 でもセグメントをほぼ使わない。すべてのセグメントを「先頭 0、大きさ 4GB」にしてセグメントの変換を事実上なくし、保護も変換もページングで行う。x86-64 では、セグメントの機能そのものがほとんど削られた（一般知識、未確認）。
- 歴史的にはセグメント方式が先にあり、今はページ方式に落ち着いた。RISC-V は最初からページ方式だけを選んだ設計と言える。
- `kernel.ld` で分けた `.text`、`.rodata`、`.data`、`.bss` は、セグメントに似て見えるが、CPU のセグメントの仕組みではない。ただの並べ方の区切り。推論：ページの権限（`R`、`W`、`X`）と組み合わせると、セグメントでやっていた「この範囲はコードだから書き込み禁止」に近いことができる。

## デマンドページングと仮想記憶（486 本 9.1）

### デマンドページング

- プログラムは、使うメモリの全部を同時に必要とするわけではない。今使っている部分だけ、論理ページ（仮想アドレスのページ）と物理ページの対応が付いていればよい。
- そこで、起動するときは、実行ファイルのうち実行を始める部分のページだけを物理ページに読み込み、対応を付けて走らせる。残りは、必要になったときに読み込む。これをデマンドページングと呼ぶ。
- 起動時に全部を読み込まないので、プログラムを早く起動できる。

### ページアウトとページイン

デマンドページングを広げると、仮想記憶になる。物理メモリが足りなくなったら、あまり使われていないページの中身をディスクに逃がし、空いた物理ページを使い回す。

最初の状態：論理ページ B は物理ページ P に対応している。論理ページ A は、まだどの物理ページにも対応していない（A の中身はディスクにある）。

```
 logical pages        page table          physical pages       disk (swap)
 +-----------+                            +------------+       +-----------+
 |  page A   |  ---- (no mapping) ----    |            |       | A content |
 +-----------+                            +------------+       +-----------+
 |  page B   |  -------------------->     |  page P    |       |           |
 +-----------+                            |  (B data)  |       |           |
                                          +------------+       +-----------+
```

プログラムが A に触れたときの流れ：

```
 program            CPU                    OS (page fault handler)           disk
    |                |                              |                         |
    | (1) access A   |                              |                         |
    |--------------->|                              |                         |
    |                | no mapping -> page fault     |                         |
    |                |----------------------------->|                         |
    |                |                              | choose a victim: B on P |
    |                |                              | (2) page out:           |
    |                |                              |     write P to disk --->|
    |                |                              | (3) unmap B -> P        |
    |                |                              | (4) map A -> P          |
    |                |                              | (5) page in:            |
    |                |                              |     read A into P <-----|
    |                |  return from exception       |                         |
    |                |<-----------------------------|                         |
    | retry access A |                              |                         |
    |--------------->| OK (A -> P)                  |                         |
```

最後の状態：

```
 logical pages        page table          physical pages       disk (swap)
 +-----------+                            +------------+       +-----------+
 |  page A   |  -------------------->     |  page P    |       |           |
 +-----------+                            |  (A data)  |       +-----------+
 |  page B   |  ---- (no mapping) ----    +------------+       | B content |
 +-----------+                                                 +-----------+
```

1. プログラムが、物理ページに対応していない論理ページ A に触れる。CPU はページフォールト（例外の一種）を起こし、OS に制御が移る。
2. ページアウト：OS は、物理ページを持っている論理ページのうち、あまり使われていないもの（B、物理ページ P）を選び、P の中身をディスクに書き出す。
3. B と P の対応を外す。
4. A と P の対応を付ける。抽出した本文が崩れていて、本ではこの段階を確かめられていない（推論）。
5. ページイン：A の中身をディスクから P に読み込む。
6. 例外から戻り、プログラムは A に触れた命令をもう一度実行する。今度は対応があるので、続けられる。

- 物理メモリより大きな論理アドレス空間を使えるのは、この仕組みのおかげ。本の例では、搭載メモリが 2MB でも、ディスクに 10MB のスワップ領域があれば、10MB のメモリ空間を使うプログラムを動かせる。
- 3.3 節の「仮想記憶」（p.86〜89、`memory-allocation.md`）を、ページングで実際にやる仕組みがこれ。

### この OS との関係（推論）

- ページフォールトは、486 で言うフォールトの一種。6. で「同じ命令をもう一度実行する」のは、`exception.md` で確かめた「`sepc` は例外を起こした命令そのものを指す」と同じ形。RISC-V では、PTE の `V`（有効）ビットが 0 のページに触れるとページフォールトになり、`scause` で命令の取り出し・読み込み・書き込みのどれかが分かる（一般知識）。
- この OS は、ページアウトとページインをしない。ディスクへのスワップがなく、必要なページはすべて先に対応を付けておく。ページフォールトが起きたら、今の `handle_trap` と同じく `PANIC` する。
